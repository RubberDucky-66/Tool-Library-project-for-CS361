# Tool Library Q & A:
Add questions whenever you like

## Q1: Since the tool library requires a valid county library card, should the system for the tool library be integrated with the already existing library system or should it be separate? Will users need a separate card for the Tool Library, or will their existing County Library card work?
A1: The library card systems for books and the tools should be the same one.
Their existing card will work. Also, they can sign up for the card at
the tool library or the book library.

## Q2: Will the new system be used for both the County Library and the two lending libraries?
A2: The new system is going to be separate from the system that manages the
book loans. We just want to use the same card.

## Q3: In the statement "Checkouts are up to two weeks", does this mean there are items that are less than two weeks?
A3: We have some items that are shorter than two-week checkouts.

## Q4: How would you like the system to handle late or overdue items? Should an account be restricted from checking out more tools until the issue is resolved, or should there be another process?
A4: If items are late, we'd like to prevent further checkouts. We also
assess increasing late fee.

## Q5: Depending on the above, would a Tool Library account restriction also block regular library checkouts, and vice versa?
A5: Regular library book checkouts should not be blocked if there are late
tool returns pending. Likewise, late books should not block tool
checkouts.

## Q6: Are there any restrictions on tools, such as age requirements, required training, approval, or liability waivers?
A6: 
An electronic waiver needs to be kept for any tool rentals to happen.
They should just do this once. None of the tools require training. Tools can only be borrowed by patrons 18 and over.

## Q7: Should the system handle holds and reservations on tools? If so, should users be able to cancel reservations, and what should happen if someone reserves a tool but does not pick it up?
A7:  Tools can be reserved on a wait list. Users on the wait list can cancel at any time and be taken off the wait list. Once they reach the front of the list, they have three days to pick up the tool, or the next person on the list moves to the front.

## Q8: Are patrons expected to pay a membership fee, deposit, or replacement insurance fee specifically for the tool lending service, or is it fully covered under their standard county library card privileges?
A8:  There are no extra fees or insurance on the tool loans.

## Q9: For inventory tracking, will tools require distinct barcodes or serial numbers?
A9: Yes. We'll have an internal ID number for each, and we'd like them barcoded.

## Q10: Does the system need to handle verification of different staff roles and account permissions?
A10: Clerk: can check items in and out and issue new library cards Cataloger: everything the clerk can do, but can also add and remove inventory.  Manager: everything the cataloger can do, but can also add and remove catalogers and clerks from the system, or change employee roles.

## Q11: What information should be recorded for both patron and tool histories, and for how long? Should the system keep borrowing, return, and maintenance records for each tool?
A11: We'd like to keep records of which patrons borrowed which tool, when, and for how long. And we'd like to keep those records indefinitely.

## Q12: Will users be able to link their library card to their phones?
A12:  We won't have a way to link library cards to phones at this time.

## Q13: Will there be a website or mobile app where users can see what they have checked out, due dates, past fees, and other account information?
A13: There will be a website where users can see what their checked out status is, what holds they have, due dates, and what fees are due. There will also be a way to reserve tools from the website. We don't need a mobile app. We just want the website to be mobile-friendly.

## Q14: Will users be able to renew or extend the time they have a tool checked out?
A14: Patrons can do a one-time renewal for the same timeframe as the original checkout.

## Q15: How many people currently use the library, and how many users do you expect will use the County Tool Library?
A15: We currently have about 100,000 library cards in the system. About 5,000 of them are active on a monthly basis.

## Q16: Should the application support multiple platforms, or will it only be available on one type of device?
A16:  We don't want a specific app; we just want the website to work on all mobile and desktop devices. And Firefox.

## Q17: Will users need to create an account, and will they need to link their library card to that account before they can borrow tools?
A17: If they already have a library card, they should be able to reserve and borrow tools without any additional administrative work.

## Q18: Will users need to show identification when borrowing certain tools?
A18:  We'd like borrowers to show ID along with the card for any rentals.

## Q19: Will users be allowed to donate tools or other items to the library?
A19: People can donate to the library. But from the system's perspective, that's just a manager adding a tool to the inventory; it's not different than just purchasing a new tool and adding it to inventory.

## Q20: Will there be a strike system for users who repeatedly return tools late, damage them, or fail to return them? Will users have a reliability rating based on their borrowing history?
A20: We'll track damage and loss on a per-borrower basis. This should be viewable by the clerk doing the checkout, but generally we're not worried about deliberate damage to tools. Borrowers will be assessed
increasing late fees on lost items. And they won't be able to borrow with a lost item outstanding.

## Q21: How much will late fees cost, and what happens if someone never returns a tool they borrowed?
A21:  1 day grace period (or until closing on the next open day): No fee After that: $1/day for standard tools, $3/day for high-demand or large tools (tile saw, post-hole digger, pressure washer). Fees never exceed the tool's replacement value, or $20 per item, whichever is lower. If a tool is never returned, the late fees will just top out at the replacement value.

## Q22: Will users receive email or text message reminders when their tools are due?
A22: We have a text/email notification system for books that we'd like to piggyback off of.


## Q23: Will users be able to see which tools are currently available, checked out, or unavailable?
A23:Users should be able to browse all tools, and see which are available, which are unavailable, and the length of the waitlist, if any.

## Q24: Will the system track the condition of tools when they are checked out and returned, and will staff need to inspect tools when they are returned?
A24: The system should be built so that clerks can note if a tool needs servicing. They should be able to describe what needs to be done and mark the tool as "out of service". This doesn't affect the wait list;
they just have to wait until the tool is marked "in service" before they are allowed to borrow again.

## Q25: Will users be responsible for paying for tools that are lost or damaged?
A25: Borrowers will be responsible for paying for lost tools. Damage is covered by the library.

## Q26: Will there be a limit on how many tools one person can check out at a time?
A26:  Borrowers can borrow up to five tools at once.

## Q27: Will staff be able to manually add, remove, or update tools in the inventory?
A27:  Managers will be able to manually add, remove, and update inventory.

## Q28: Will users be able to search and filter tools by category, availability, or type?
A28:We'd like borrowers to be able to search and filter tools by category, availability, type, or name.


## Q29: Will the system support multiple tool-lending locations in the future?
A29: We'll possibly have more tool lending locations in the future, so we should plan for it.

## Q30: Will there be a way for staff to report broken, missing, or damaged tools and track maintenance schedules?
A30: We'll want a way for any employees to note broken, missing, or damaged tools. The tools that aren't currently borrowed can be either "ready to borrow" or "in maintenance", so we should be able to flag them either way.
